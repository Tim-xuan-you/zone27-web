# 商品資料怎麼建

真正的瓶頸不是程式，是這 200 款商品資料。這份給填資料的人看。

## 流程

1. 開 `dog-food.csv`（用 Google Sheet 或 Excel 都行）
2. 一款飼料填一列
3. 存回 `data/dog-food.csv`（**編碼選 UTF-8**）
4. 跑 `npm run data:import`
5. 有錯它會用中文告訴你第幾列哪一欄不對，**而且一列都不會寫進去**
6. 沒錯就跑 `npm run build` 確認頁面生得出來

**不要直接改 `dog-food.json`。**那是產生出來的，下次匯入會被蓋掉。

## 目標

**200–300 款嚴選，不要做到 5000 款。**

蝦皮上有幾萬種狗飼料，其中大部分是分裝包、雜牌、重複賣場。
放 5000 款進來，使用者一樣會選擇癱瘓，那就違背了「幫你刪掉」的初衷。

值得放進來的標準：**指標性品牌、規格查得到、通路穩定、有分潤連結。**

## 欄位說明

### 基本
| 欄位 | 填什麼 | 例 |
|---|---|---|
| `id` | 自己編，不能重複 | `df-001` |
| `brand` | 品牌 | `Orijen` |
| `name` | 品項全名 | `六種鮮魚無穀成犬` |

### 營養（照包裝上的保證分析填）
| 欄位 | 填什麼 |
|---|---|
| `protein` `fat` `carb` | 粗蛋白／粗脂肪／碳水，只填數字不要 % |
| `omega3` | Omega-3 % |
| `phosphorus` | 磷 %。腎臟問題的關鍵指標，一定要填 |

> 三個加起來超過 100% 會被擋下來 —— 通常是抄錯行。

### 成分
| 欄位 | 填什麼 |
|---|---|
| `proteinSources` | 只能填這些：`chicken` `beef` `lamb` `salmon` `whitefish` `duck` `turkey` `pork` `venison` `insect`。多種用 `\|` 隔開，例如 `salmon\|whitefish` |
| `singleSource` | 只有一種蛋白源就 `Y`，否則 `N`。**填 Y 但上面填了兩種以上會被擋** |
| `grainFree` | 無穀 `Y` |
| `prescription` | 處方飼料 `Y`（引擎不會主動推薦處方飼料） |
| `lifeStage` | `puppy` `adult` `senior` `all`，多個用 `\|` |
| `bodySize` | `small` `medium` `large`，多個用 `\|` |

### 使用者回報
| 欄位 | 填什麼 |
|---|---|
| `reportsTotal` | 你統計了幾則評價 |
| `reportsPalatability` | 其中幾則說不愛吃 |
| `reportsLooseStool` | 其中幾則說軟便 |

> 後兩個比第一個大會被擋。樣本少於 30 則，引擎不會拿它扣分。

### 通路與價格

**m1 = 最穩，m2 = 最省。**

- `m1` 填**官方旗艦館／蝦皮商城**那種有保障的（15 天鑑賞、正品保證）
- `m2` 填**高評價大賣家**那種比較便宜的
- 只有一個通路就只填 m1

| 欄位 | 填什麼 |
|---|---|
| `m1Label` | 顯示名稱，例如 `官方旗艦館` |
| `m1Amount` | 售價，只填數字 |
| `m1Note` | 給使用者的差異點，例如 `15 天鑑賞 · 24h 出貨` |
| `m1Url` | **你的分潤連結**（不是商品原始網址） |
| `m1Commission` | 佣金 %。**只用在揭露頁，排序演算法讀不到** |

| `unit` | 規格，例如 `1.5kg` |
| `checkedAt` | 你查價的日期，格式 `2026-09-05`。**這個會誠實顯示在網站上** |

### 最重要的一欄

| 欄位 | 填什麼 |
|---|---|
| `dealbreaker` | **「不要買，如果⋯」的那句話** |

這是整個產品的核心，**沒填會被擋下來**。

寫法：講**使用者的處境**，不要講我們多客觀。

- ❌ 「我們認為這款不適合部分犬隻」
- ✅ 「你的狗曾對羊肉起疹 — 單一蛋白源沒有備援」
- ✅ 「你的狗挑食 — 142 位回報者中有 31 位反映適口性差」
- ✅ 「碳水 34% 偏高 — 需要控制體重的狗不適合」

**用具體數字，不要用形容詞。**

### 其他
| 欄位 | 填什麼 |
|---|---|
| `discontinued` | 停產或長期缺貨 `Y`（引擎會直接排除，但仍列出理由） |

## 常見錯誤

| 訊息 | 怎麼修 |
|---|---|
| `「chikcen」不在允許清單內` | 拼錯了，照上面的清單填 |
| `checkedAt 格式要像 2026-09-05` | 用 `2026-09-05`，不要用 `9/5` |
| `回報人數比總回報數還多` | 抄錯行了 |
| `標了單一蛋白源，但填了 2 種` | 兩邊對不起來，改一邊 |
| `還是佔位連結` | 這是警告不是錯誤 —— **上線前一定要換成真的分潤連結** |

## 規格要填幾個？—— 一款一個

**預設：一款一個規格，挑「新手第一次會買」的入門包。**

不是因為做不到多規格（程式支援，同網址會列成表、不同網址會分成兩個賣場區塊），
是因為**維護成本會翻倍，而那個成本落在你身上**：

```
200 款 × 1 規格 = 200 次查價
200 款 × 2 規格 = 400 次查價 + 兩倍的單位換算與核對
```

而使用者其實沒那麼在乎。第一次換低敏飼料的人要決定的是**買哪一款**，
不是買多大包 —— 沒有人會第一次就賭 22 磅。**大包是回購第三次之後的事。**

### 例外

**每公斤省超過 25% 才值得加第二個規格。**低於那個數字，寫進 `m1Note` 就好：

```
✅  m1Note = 低致敏鮭魚 · 2~3工作日出貨 · 22磅裝每公斤便宜 29%
❌  另外開一整組欄位去維護 22 磅的價格
```

一句話講完，零維護成本。使用者想買大包，進賣場自己看得到。

**我們的價值是「幫他選對品項」，不是「幫他算包裝規格」——後者賣場自己會做。**

### m2 留給誰

**留給真的不同的賣家**（例如官方旗艦館 vs 高評價大賣家），不是留給大包。

同一家的不同規格，如果賣家放在同一個商品頁，`m1Unit` / `m2Unit` 填不同容量就會
自動列成表；如果賣家拆成兩個商品（網址不同），就會顯示成兩個賣場區塊 ——
兩種都支援，但都不是預設該做的事。
