# 第四個類目：貓砂（cl-）

2026-09-18 決定。Tim：「三個類別處理完了？接續下一類別吧，一樣寵物？還是有其他建議？」

## 為什麼是貓砂

1. **同一批讀者。** 帳號只有一個（2026-09-18 改成 `zone27.tw` 一個帳號打全站），所以下一個類目要嘛服務同一群人，要嘛得重新養一群人。養貓的人每個月都要買砂。
2. **重複購買。** 飼料一包吃一個月，貓砂也是一個月，但貓砂沒有「換糧要適應」的心理成本，換得比飼料勤，回頭率高。
3. **真的有人選不出來。** 礦砂、豆腐砂、木屑砂、紙砂、水晶砂、混合砂，六種材質的優缺點互相矛盾，而且量法不同（礦砂論公斤、豆腐砂論公升），讀者根本比不出哪個貴。
4. **有一個像「藏雞」的發現**（每個類目都要有，見品牌系統）：
   - **寫「可沖馬桶」的，有一半沖了會塞。** 豆腐砂適量沖可以；木屑砂遇水是散開不是溶解，會卡在管線；礦砂主成分不溶於水，絕對不能沖。但賣場文案常常混在一起寫。
   - **每公斤最便宜的，用起來不一定最便宜。** 便宜礦砂用量大、垃圾重；好的豆腐砂吸得多、用得省。要算的是「一個月多少錢」，不是「一包多少錢」。
5. **蝦皮有分潤。** 反過來說，手機、遊戲主機、遊戲點數、電子票券、黃金、汽機車這幾類蝦皮平台不給分潤，做了也拿不到錢，所以 3C 那條路先不要走。

## 資料要記什麼（LitterSpec）

飼料那套 Spec（蛋白、脂肪、碳水）在這裡完全用不上，貓砂要記的是另一組：

| 欄位 | 說明 | 為什麼要 |
|---|---|---|
| `material` | mineral／tofu／wood／paper／crystal／mixed | 所有判斷的根 |
| `clumping` | 會不會結團 | 不結團的要整盆換，成本算法不同 |
| `flushable` | yes／limited／no | 我們的招牌判定。limited＝適量可以，整盆倒會塞 |
| `flushClaim` | 賣場或包裝上寫的 | 用來對照：包裝寫可沖、實際 limited 或 no 的，就是這一類的「藏雞」 |
| `dust` | low／medium／high（品牌宣稱） | 家裡有人過敏、有呼吸道問題的第一刀 |
| `scented` | 有沒有加香精 | 貓對香精接受度低，也是退貨主因 |
| `grain` | 顆粒粗細 fine／medium／coarse | 落砂、貓掌帶砂 |
| `packUnit` | kg 或 L | 兩種量法不能直接比，要各自換算 |
| `packSize` | 一包多少（數字） | 每公斤／每公升單價 |
| `monthlyUse` | 一隻貓一個月大概用幾包（品牌建議或我們的推估） | 「一個月多少錢」的分母，推估一定要寫出來 |
| `tracking` | 落砂程度 low／medium／high | 讀者抱怨第一名 |
| `deodorizer` | 活性碳／沸石／植物纖維／香精／無 | 除臭是怎麼做到的 |
| `kittenNote` | 幼貓要注意的（例如細顆粒礦砂會誤食） | 不寫成醫療建議，只寫廠商標示與常見說法 |

## 刪掉的規則（引擎）

飼料的規則是過敏原、年紀、體型；貓砂的規則是家裡的條件：

- 「要沖馬桶」→ 只留 flushable=yes／limited，並且把 limited 的限制講清楚
- 「家裡有人過敏／怕粉塵」→ 刪掉 dust=high 和 scented
- 「貓會吃砂」→ 刪掉細顆粒礦砂（照廠商標示寫，不下醫療判斷）
- 「預算有限」→ 照一個月多少錢排，不是照一包多少錢
- 「住公寓、垃圾要拿下樓」→ 重量排序（礦砂一個月十幾公斤）

## 做法

- 商品編號 `cl-`，CSV `data/cat-litter.csv`，Sub id 第二格 `catlitter`
- 共用的：賣場名冊、連結管理（paste／links:check）、/go 跳轉、維護台、分享卡、設計
- 不共用的：規格、判定規則、商品頁上的數字區塊
- 型別走 `lib/litter.ts`，不要硬塞進飼料的 Spec。Form 多一個 "litter"，編譯器會把該處理的地方全部指出來

## 招牌頁

`/cat-litter/flush`（暫名）：**「哪些貓砂真的可以沖馬桶」**
一張表，每一款寫包裝怎麼寫、實際能不能沖、沖了會怎樣。跟 /check 同一個作法：查得到、可以分享、有雞的給替代。
